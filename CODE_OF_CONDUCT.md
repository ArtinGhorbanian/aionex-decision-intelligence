# AIONEX Code of Conduct

## Purpose

AIONEX is a private pre-release project. Authorized collaborators are expected to make its repository, reviews, issue discussions, security work, and other project spaces safe, focused, and respectful.

This code applies to project participation. It does not create a public community, employment relationship, service commitment, or release authorization.

## Expected conduct

Participants should:

- communicate with patience, clarity, and respect;
- discuss the work rather than attacking the person;
- welcome good-faith questions and acknowledge uncertainty;
- give specific, actionable review feedback;
- respect privacy, confidentiality, access restrictions, and embargoed security information;
- avoid exposing personal data, credentials, client material, or private provider details;
- disclose relevant conflicts, limitations, and rights concerns;
- correct unsupported product, security, ownership, or provider claims;
- prioritize user safety and responsible decision support over presentation or speed;
- stop and seek authorization when a task would expand the legal, security, privacy, provider, or deployment boundary.

## Unacceptable conduct

The following are not acceptable in project spaces:

- harassment, intimidation, threats, stalking, or discriminatory conduct;
- insults, sustained disruption, or deliberate humiliation;
- sexualized language, imagery, or unwanted attention;
- publishing another person's private information or project-confidential material;
- retaliating against a good-faith concern or review;
- pressuring someone to conceal a security, safety, rights, or attribution issue;
- using repository access to test systems or data without authorization;
- misrepresenting authorship, ownership, endorsement, customer use, performance, readiness, or compliance;
- introducing secrets, malware, covert telemetry, hidden network calls, or intentionally deceptive behavior.

## Scope

This code applies in:

- source-control discussions and pull requests;
- issue and planning systems;
- private security advisories;
- project meetings and written collaboration;
- demonstrations or communications made in an AIONEX project role.

Conduct outside those spaces may be considered when it creates a direct safety, confidentiality, or participation risk for the project.

## Reporting a concern

Use an already-established private maintainer channel. If the concern involves a vulnerability or sensitive technical detail, follow [SECURITY.md](SECURITY.md) and use a private GitHub security advisory once an access-controlled remote exists.

Do not place personal data, confidential evidence, credentials, or exploit details in a public or ordinary issue. This repository does not publish an email address or external reporting domain.

## Response and enforcement

Authorized maintainers should handle reports discreetly, avoid unnecessary disclosure, allow affected participants to provide relevant context, and choose a proportionate response. Possible actions include:

1. a private clarification or correction;
2. a warning and required change in behavior;
3. removal from a discussion or task;
4. temporary restriction of repository access;
5. removal of repository access;
6. escalation through an already-authorized organizational or legal process when required.

Conflicts of interest should be disclosed, and a different authorized reviewer should handle the matter when practical. No response-time, appeal, or confidentiality guarantee is promised beyond reasonable private handling within the project's available controls.
